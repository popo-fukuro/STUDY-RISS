# 試験ガイド：情報処理安全確保支援士（SC）

> 調査日：2026年11月22日（IPA・経済産業省の公式発表を中心に整理）
> 制度は変わることがあるため、申込・受験の前には必ずIPA公式サイトで最新情報を確認すること。

---

## 0. まず押さえるべき最重要ポイント（2026年11月時点）

1. **令和8年度（2026年度）からCBT方式に変わった。** 紙の試験から、テストセンターのパソコンで受験する方式に変わった。春期・秋期は「前期・後期」になった。
2. **名前が変わった。** 午前Ⅰ→**科目A-1**、午前Ⅱ→**科目A-2**、午後→**科目B**。出題範囲・形式・問題数・試験時間・合格基準は変わっていない。
3. **科目Aと科目Bは別の日に受ける。** 1日で終わらなくなった。
4. **令和8年度後期（2027年2〜3月）は、記述式の科目Bを受けられる最後の回になる見込み。** 2027年度の夏〜秋頃から新制度に移り、科目Bは「120分・12問・全問解答・選択式（サンプル問題時点）」に変わる予定（検討段階）。
5. **CBT化した令和8年度以降の問題は公開されない。** 公式の過去問・解答例・採点講評は**令和7年度秋期まで**。

## 1. 資格の概要

| 項目 | 内容 |
|---|---|
| 正式名称 | 情報処理安全確保支援士（Registered Information Security Specialist：RISS） |
| 通称 | 支援士、セキスペ、登録セキスペ、SC |
| 種類 | 国家資格（「情報処理の促進に関する法律」に基づく）／**名称独占資格**（士業） |
| 創設 | 2016年10月（試験は2017年春期から。前身は「情報セキュリティスペシャリスト試験」） |
| 実施機関 | IPA（独立行政法人 情報処理推進機構） |
| レベル | 共通キャリア・スキルフレームワークのレベル4（高度試験と同じ最上位レベル） |
| 受験資格 | なし（誰でも受験可能） |
| 試験合格の有効期限 | なし。合格すれば、登録はいつでも申請できる |

### 「試験合格」と「登録」は別物

- **試験に合格しただけ**では「情報処理安全確保支援士試験 合格者」。
- **IPAに登録して初めて**「情報処理安全確保支援士（登録セキスペ）」を名乗れる（名称独占）。
- 登録すると、登録証（カード）が交付される。名刺などに資格名とロゴマークを載せられる。

### 登録セキスペの主な義務

- 信用失墜行為の禁止
- **秘密保持義務**（違反すると罰則あり）
- **講習の受講義務**（毎年のオンライン講習と、3年に1回の実践講習）

### 想定される人物像（業務と役割）

情報セキュリティマネジメント、システムの企画・設計・開発・運用でのセキュリティ確保、セキュリティ対策の適用、インシデント管理の業務に従事する。これらで主導的な役割を果たし、下位者を指導する人材。

## 2. 試験の構成（令和8年度・CBT方式）

| 科目（旧名称） | 試験時間 | 出題形式 | 出題数／解答数 | 合格基準 |
|---|---|---|---|---|
| **科目A-1**（午前Ⅰ） | 50分 | 多肢選択式（四肢択一） | 30問／30問 | 60点以上／100点 |
| **科目A-2**（午前Ⅱ） | 40分 | 多肢選択式（四肢択一） | 25問／25問 | 60点以上／100点 |
| **科目B**（午後） | 150分 | 記述式 | 4問から2問を選択 | 60点以上／100点 |

- A-1とA-2の間には10分の休憩がある。
- **すべての科目で60点以上を取れば合格。**
- 採点は順番に行う（多段階選抜）。A-1が基準点に届かないとA-2は採点されず、A-2が届かないと科目Bは採点されない。
- 科目Bは1問50点×2問。
- 記述式の解答もキーボードで入力する。

### CBTならではの注意点

- **受験票は郵送されない。** 当日は顔写真付きの本人確認書類が必要。
- **問題に直接書き込めない。** 画面上のメモ機能と電卓機能のほか、メモ用紙1枚と筆記用具が配られる。自分で持ってきたものは使えず、メモ用紙は試験後に回収される。
- 持ち込める飲み物は、ラベルをはがしたペットボトルの水（1000ml以下）1本だけ。
- 科目Aの得点は試験終了後に画面に表示される。科目Bの得点は画面に表示されない。
- 申込みは前期・後期それぞれ1回だけ。複数の区分には申し込めない。
- 科目A群と科目B群は同時に予約する。
- 受験手数料：**7,500円（非課税）**

## 4. 免除制度

### 科目A-1の免除（いちばんよく使われる）

次のどれかに当てはまると、**2年間**（合格や基準点到達から2年後の同じ時期まで）A-1が免除される。

- 応用情報技術者試験（AP）に合格した
- いずれかの高度試験または支援士試験に合格した
- 高度試験・支援士試験の午前Ⅰ（科目A-1）で基準点以上を取った

**令和8年度の対象**
- 前期：2024年春期・秋期、2025年春期・秋期の合格者と午前Ⅰ通過者
- 後期：2024年秋期、2025年春期・秋期の合格者と午前Ⅰ通過者、**2026年度前期のAP・高度・SC合格者とA-1通過者**

### 科目A-2の免除

IPAが認定した学科等の課程を修了し、修了認定を受けた人が対象。

## 5. 出題範囲

### 科目A-1（共通知識）

応用情報技術者試験の午前（科目A）80問の中から30問が選ばれる。

- テクノロジ系：約17問（基礎理論、コンピュータシステム、技術要素、開発技術）
- マネジメント系：約5問（プロジェクトマネジメント、サービスマネジメント、システム監査）
- ストラテジ系：約8問（システム戦略、経営戦略、企業と法務）

### 科目A-2（専門知識）

| 分野 | 技術レベル | 重要度 |
|---|---|---|
| **情報セキュリティ** | 4 | ◎（出題の中心） |
| ネットワーク | 4 | ○ |
| データベース | 3 | ○ |
| システム開発技術 | 3 | ○ |
| ソフトウェア開発管理技術 | 3 | ○ |
| サービスマネジメント | 3 | ○ |
| システム監査 | 3 | ○ |

※セキュリティ関連の法律・ガイドライン（不正アクセス禁止法、個人情報保護法、サイバーセキュリティ基本法、サイバーセキュリティ経営ガイドラインなど）も出る。

### 科目B（記述式）の4つの柱

1. 情報セキュリティマネジメントの推進または支援
2. 情報システムの企画・設計・開発・運用でのセキュリティ確保の推進または支援
3. 情報および情報システムの利用におけるセキュリティ対策の適用の推進または支援
4. 情報セキュリティインシデント管理の推進または支援

### 科目Bの頻出テーマ（過去問の傾向）

| ジャンル | よく出るキーワード |
|---|---|
| Webセキュリティ | XSS、CSRF、SQLインジェクション、CSP、Cookie属性（Secure/HttpOnly/SameSite）、セッション管理 |
| 認証・認可 | OAuth 2.0、OpenID Connect、SAML、多要素認証、FIDO／パスキー、JWT |
| 暗号・PKI | TLS、サーバ証明書、証明書チェーン、ハッシュ、デジタル署名、鍵管理 |
| メール | SPF、DKIM、DMARC、S/MIME、標的型メール |
| ネットワーク | ファイアウォール、プロキシ、DNS（DNSSEC、キャッシュポイズニング）、VPN、IDS/IPS、WAF |
| クラウド・ゼロトラスト | IaaS/SaaS の責任共有モデル、CASB、IDaaS、EDR、SASE |
| インシデント対応 | ログ分析、マルウェア解析、C&Cサーバ、ラテラルムーブメント、フォレンジック、CSIRT |
| セキュアプログラミング | C/C++のバッファオーバーフロー、Java・Python・JavaScriptなどのコードの脆弱性 |
| マネジメント | リスクアセスメント、サプライチェーンリスク、脆弱性管理、委託先管理、規程類 |

※令和7年度秋期の問1では、Webアプリへの攻撃とCSP（Content Security Policy）が出題され、CSPの設問は正答率が低かった（IPA採点講評）。

## 6. 合格率などの統計

| 試験回 | 応募者 | 受験者 | 合格者 | 合格率 |
|---|---|---|---|---|
| 令和6年度秋期 | 24,032 | 17,324 | 2,615 | 15.1% |
| 令和7年度春期 | 22,645 | 16,526 | 3,134 | 19.0% |
| 令和7年度秋期 | 26,385 | 18,816 | 4,199 | **22.3%**（過去最高） |

- 令和7年度秋期の合格者の平均年齢は34.4歳。
- 令和5年度秋期に午後Ⅰと午後Ⅱが「午後」1つにまとまって以降、合格率はだいたい15〜22%で推移している。
- 令和7年度秋期の合格率が高かった理由として、午前Ⅱがやさしめで、苦手な人が多いセキュアプログラミングの出題が少なかったことが挙げられている（アイテックの分析）。

## 7. 勉強法の基本

### 科目A-1
- 応用情報の午前過去問を繰り返し解く。
- APに合格していれば2年間は免除される。

### 科目A-2
- **過去問がそのまま、またはよく似た形で繰り返し出る。** 過去5〜6年分を何周も解くのが最も効率がいい。
- 正解の選択肢だけでなく、**ほかの選択肢がなぜ間違いか**も説明できるようにする。

### 科目B（合否を分ける本丸）
- IPA公式の過去問・解答例・採点講評（令和7年度秋期まで）で演習する。
- 記述のコツ
  - 問題文の言葉を使って答える（自分の言葉で言い換えすぎない）。
  - 「〜字以内で」の指定を守る。「何が」「どうなるから」「どうなる」の因果をはっきり書く。
  - 答えのヒントは問題文の中にあることが多い。図表・ログ・設定は細かく読む。
- 4問から2問を選ぶので、得意ジャンル（Web、ネットワーク、マネジメントなど）を2〜3つ作っておく。
- **CBT対策**：問題文に線を引けないので、メモ用紙1枚と画面のメモ機能で情報を整理する練習をする。記述はキーボードで打つ練習をしておく。

### 勉強時間の目安
- 応用情報合格レベルの人で、だいたい200時間前後と言われることが多い（個人差は大きい）。

## 8. 合格後：登録と資格の維持

| 項目 | 内容 |
|---|---|
| 登録費用 | 登録手数料 10,700円（非課税）＋登録免許税 9,000円 |
| 登録日 | 年2回（**4月1日**と**10月1日**）。申請は1年中受け付けている |
| 有効期限 | 登録日（または更新日）から**3年** |
| 更新手数料 | なし（ただし講習を全部修了していることが条件） |
| オンライン講習 | **毎年1回**、標準6時間、受講料20,000円（非課税） |
| 実践講習 | **3年に1回**、IPAまたは民間事業者（特定講習）から選ぶ |
| 実務経験者の講習制度 | 2026年4月から始まった制度。認められた実務経験があれば、実践講習の代わりにできる |

- 更新申請は、有効期限の60日前までに行う。
- 講習を受けないと更新できず、登録が切れる。

## 9. 2027年度からの新制度（検討段階・変更の可能性あり）

IPAと経済産業省が2026年3月31日に公表した見直し案（4月28日更新）のポイント。

- 応用情報と高度試験は「**プロフェッショナルデジタルスキル試験（仮称）**」にまとめられる。
- **情報処理安全確保支援士試験は独立した試験として残る**（名前も変わらない）。
- SCの新制度は**2027年度の夏頃〜秋頃**に始まる予定。

| 科目 | 現行（令和8年度） | 新制度案 |
|---|---|---|
| 科目A-1 | 50分・30問 | 45分・30問 |
| 科目A-2 | 40分・25問 | 35分・25問 |
| 科目B | 150分・記述式・4問から2問選択 | **120分・12問（全問解答）**。サンプル問題では選択式（1問1答が8問、1問3答が4問の計20設問） |

- 科目Aの分野が「ビジネス」「テクノロジ」「セキュリティ・倫理」に再編される。
- 科目Bではマネジメント分野が強化される。
- 科目Bは、得意分野だけで勝負できなくなり、全範囲をまんべんなく、速く解く力が必要になる。
- 現行試験で得た免除を、新制度でも一定期間使えるようにする経過措置が検討されている。

## 10. よく出る略語・用語ミニ辞典

| 用語 | ひとことで |
|---|---|
| CIA | 機密性（Confidentiality）・完全性（Integrity）・可用性（Availability）。情報セキュリティの3要素 |
| XSS | Webページに悪意あるスクリプトを埋め込み、閲覧者のブラウザで実行させる攻撃 |
| CSRF | ログイン中の利用者に、本人が意図しないリクエストを送らせる攻撃 |
| SQLインジェクション | 入力欄にSQL文を混ぜてデータベースを不正に操作する攻撃 |
| CSP | ブラウザが読み込んでよいスクリプトなどの読込み元を、サーバ側から指示する仕組み |
| SPF／DKIM／DMARC | 送信元ドメインのなりすましメールを見抜く仕組み（送信元IP／電子署名／それらを使った判定ポリシー） |
| TLS | 通信を暗号化し、サーバが本物か確かめるプロトコル |
| PKI | 公開鍵が本人のものかを、認証局（CA）の証明書で保証する仕組み |
| OAuth 2.0 | 「権限を委譲する」仕組み（認可）。パスワードを渡さずにアクセス権だけ渡す |
| OpenID Connect | OAuth 2.0を土台にした「本人確認」の仕組み（認証） |
| SAML | 主に企業向けのシングルサインオン（SSO）で使われる認証連携の規格 |
| FIDO／パスキー | パスワードを使わず、端末内の秘密鍵と生体認証などでログインする仕組み |
| WAF | Webアプリへの攻撃（SQLi、XSSなど）を検知・遮断するファイアウォール |
| IDS／IPS | 不正な通信を検知する（IDS）／検知して遮断する（IPS）仕組み |
| EDR | 端末上の怪しい挙動を監視し、侵入後の対応を助けるツール |
| SIEM | 各機器のログを集めて相関分析し、攻撃の兆候を見つけるツール |
| CSIRT | セキュリティインシデントに対応する組織内のチーム |
| ゼロトラスト | 「社内だから安全」と考えず、すべてのアクセスを毎回確認する考え方 |
| APT | 特定の組織を長期間ねらい続ける標的型攻撃 |
| C&Cサーバ | 感染端末に命令を送る攻撃者のサーバ |
| ラテラルムーブメント | 侵入した端末から、社内のほかの端末へ横に広がっていくこと |
| DNSキャッシュポイズニング | DNSサーバに偽の情報を覚えさせ、偽サイトへ誘導する攻撃 |
| DNSSEC | DNSの応答に電子署名を付けて、改ざんされていないことを確かめる仕組み |
| バッファオーバーフロー | 確保した領域を超えてデータを書き込み、プログラムを乗っ取る攻撃 |
| ISMS | 情報セキュリティマネジメントシステム（ISO/IEC 27001） |
| CVSS | 脆弱性の深刻度を数値で評価する共通の基準 |
| SBOM | ソフトウェアに含まれる部品（ライブラリなど）の一覧 |
